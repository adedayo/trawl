# Wails build assets

Files here are inputs to `wails build`. Two of them are deliberately absent:

- `build/windows/installer/wails_tools.nsh` — regenerated by the Wails CLI on
  every build from `wails.json`. Committing it would freeze the values it is
  supposed to interpolate.
- `build/bin/` — build output, git-ignored.

Everything else is committed and is a source file:

| File | Purpose |
|---|---|
| `appicon.png`, `appicon.svg` | Source icon; Wails derives the macOS `.icns` |
| `darwin/Info.plist` | Bundle metadata for release builds |
| `darwin/Info.dev.plist` | Bundle metadata for `wails dev` |
| `windows/icon.ico` | Multi-resolution icon (16–256px), generated from `appicon.png` |
| `windows/info.json` | Windows version resource embedded in the `.exe` |
| `windows/wails.exe.manifest` | DPI awareness, common controls, `asInvoker` |
| `windows/installer/project.nsi` | NSIS installer definition |

## Regenerating `windows/icon.ico`

```sh
python3 - <<'PY'
from PIL import Image
src = Image.open("build/appicon.png").convert("RGBA")
src.save("build/windows/icon.ico", format="ICO",
         sizes=[(16,16),(24,24),(32,32),(48,48),(64,64),(128,128),(256,256)])
PY
```

The 256px entry is what Explorer uses for large-icon views; omitting it makes
the application look blurry in exactly the place users first see it.

## Bundle identifier

`com.adedayo.trawl`, set in both plists. It is not `com.wails.trawl` — the
Wails default — because the identifier is what macOS keys preferences, saved
state, notification permissions and, once signing is in place, the signing
certificate against. Changing it later orphans all of them.
